## Repository Purpose

Documentation and Docker Compose configurations for a Raspberry Pi 5 home server running self-hosted services: Immich (photos), Paperless-ngx (documents), Actual Budget (finance), Home Assistant (automation), and Sport Kiosk (live scores).

## Architecture

### Hardware
- Raspberry Pi 5 (16GB RAM) running Ubuntu Server 24.04 LTS
- 32GB SD Card for OS, 1TB SSD mounted at `/mnt/storage` for data
- Remote access via Tailscale VPN

### Service Port Map
| Service | Port | Notes |
|---------|------|-------|
| Immich | 2283 | Photo management |
| Paperless-ngx | 8000 | Document management |
| Sport Kiosk | 3000 | Live sports scores |
| Actual Budget | 5006 | HTTPS required (uses nginx proxy) |
| Home Assistant | 8124 | Non-default port to avoid conflicts |

### Storage Pattern
All persistent data lives on the SSD at `/mnt/storage/<service>/`:
```
/mnt/storage/
├── immich/           # Photo uploads
├── immich-db/        # Immich PostgreSQL
├── paperless/        # Documents, database, redis
├── actual-budget/    # Budget files, SSL certs
└── homeassistant/    # Home Assistant config
```

Docker Compose files reference these paths via volume mounts.

## Docker Compose Patterns

### Standard Service Structure
Each service directory contains:
- `docker-compose.yml` - Service definition
- `README.md` - Setup and usage documentation
- `.env` (some services) - Environment variables

### Common Commands
```bash
# Start a service
cd <service-dir>
COMPOSE_HTTP_TIMEOUT=200 docker-compose up -d

# View logs
docker logs -f <container-name>

# Update service
docker-compose pull && docker-compose up -d
```

### Compose v1 Compatibility
Use `docker-compose` (with hyphen) on the Pi. Avoid `name:` key in compose files as it requires Compose v2.

### Resource Optimization
Services are configured for Pi's limited resources:
- Immich: ML disabled (`immich-machine-learning` commented out)
- Paperless: OCR skipped, single workers (`PAPERLESS_OCR_MODE: skip`, `PAPERLESS_TASK_WORKERS: 1`)
- Home Assistant: Uses `network_mode: host` for device discovery

### Healthchecks
All services should include healthchecks:
```yaml
healthcheck:
  test: ["CMD", "curl", "-f", "http://localhost:PORT"]
  interval: 30s
  timeout: 10s
  retries: 3
```

For services with dependencies, use:
```yaml
depends_on:
  database:
    condition: service_healthy
```

## Network Configuration

### Local Access
- Pi IP: `192.168.0.105` (may vary)
- Services accessible at `http://<pi-ip>:<port>`

### Remote Access (Tailscale)
- Tailscale IP: `100.126.21.128`
- Requires Tailscale running on both client and Pi

### SSL/HTTPS
Actual Budget requires HTTPS for SharedArrayBuffer. Uses self-signed certs generated by `setup-ssl.sh` with nginx reverse proxy.

## Adding New Services

1. Create directory: `mkdir <service-name>`
2. Create `docker-compose.yml` with:
   - Volumes pointing to `/mnt/storage/<service>/`
   - Healthcheck configuration
   - `restart: unless-stopped`
3. Create `README.md` with setup instructions
4. Create directories on Pi: `sudo mkdir -p /mnt/storage/<service>`
5. Set permissions: `sudo chown -R 1000:1000 /mnt/storage/<service>`

## Troubleshooting

### Container Name Conflicts
```bash
docker rm -f <container-name>
docker-compose up -d
```

### Timeout Errors on Pi
Increase timeout for slow SD card/image pulls:
```bash
COMPOSE_HTTP_TIMEOUT=200 docker-compose up -d
```

### Service Won't Start
```bash
docker logs <container-name>
docker-compose down && docker-compose up -d
```

### Storage Mount Issues
Verify SSD is mounted: `df -h /mnt/storage`
