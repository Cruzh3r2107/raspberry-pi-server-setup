## What is Actual Budget

Actual Budget is a local-first personal finance application based on the zero-based budgeting methodology. Originally a paid service, it was open-sourced in 2022 and is now completely free and self-hostable.

**Key Features:**
- **Zero-based budgeting** - Every dollar has a job, inspired by YNAB (You Need A Budget)
- **Local-first architecture** - Your data lives on your server, works offline
- **End-to-end encrypted sync** - Sync across devices with full encryption
- **Bank sync** - Import transactions automatically (via SimpleFIN or manual import)
- **Multi-budget support** - Manage multiple budgets (personal, business, family)
- **Tracking accounts** - Monitor loans, investments, assets without budgeting them
- **Reports and insights** - Net worth tracking, spending trends, category analysis
- **Mobile apps** - iOS and Android apps available
- **Import from other tools** - Import from YNAB, Mint, CSV files

**Perfect for:**
- Personal budget tracking and expense management
- Monthly zero-based budgeting (envelope method)
- Net worth tracking across accounts
- Debt payoff planning
- Savings goal setting
- Family budget collaboration
- Privacy-focused finance management (data stays on your server)

## Installation

### Prerequisites

Docker must be installed (see [Immich setup](../immich/) for Docker installation).

### 1. Create Directories

```bash
mkdir -p /mnt/storage/actual-budget
chmod -R 755 /mnt/storage/actual-budget

mkdir -p /home/vish/home-server/actual-budget
cd /home/vish/home-server/actual-budget
```

### 2. Create docker-compose.yml

The docker-compose.yml file has already been created at:
`/home/vish/home-server/actual-budget/docker-compose.yml`

Configuration uses:
- **Port:** 5006 (local and Tailscale)
- **Storage:** `/mnt/storage/actual-budget` (on SSD, not SD card)
- **Timezone:** America/Chicago
- **Restart policy:** unless-stopped (auto-starts on reboot)
- **Healthcheck:** Automated health monitoring every 60 seconds

### 3. Generate SSL Certificates

Actual Budget requires HTTPS to enable SharedArrayBuffer (needed for core functionality). Run the setup script to generate self-signed certificates:

```bash
cd /home/vish/home-server/actual-budget
./setup-ssl.sh
```

This creates SSL certificates valid for 10 years, configured for:
- Local network IP (auto-detected)
- Tailscale IP (100.126.21.128)
- localhost

### 4. Start Actual Budget

```bash
cd /home/vish/home-server/actual-budget
docker compose up -d
```

**First start takes 30-60 seconds:**
- Pulling Docker images (actual-server + nginx, if not cached)
- Starting Node.js server and Nginx reverse proxy
- Initializing data directory
- Binding SSL certificates

### 5. Monitor Startup

```bash
# Check both containers are running
docker ps | grep actual

# View Actual server logs
docker logs -f actual-budget

# View Nginx logs
docker logs -f actual-budget-nginx
```

Wait until you see: `Listening on :::5006...`

Press Ctrl+C to exit logs.

## Initial Setup

### 1. Access Web Interface

Open browser (HTTPS required):
- **Local network:** `https://192.168.0.104:5006`
- **Remote via Tailscale:** `https://100.126.21.128:5006`

**Important:**
- Must use `https://` (not `http://`)
- Browser will show security warning about self-signed certificate
- Click "Advanced" → "Proceed" (or "Accept Risk" depending on browser)
- This is safe for local network use - the certificate was generated by you

### 2. Create Your First Budget

On first access, Actual Budget will prompt you to:

**Option A: Create New Budget**
1. Click **"Create New Budget"**
2. Enter a budget name (e.g., "Personal Budget")
3. Click **"Create"**

**Option B: Import Existing Budget**
1. Click **"Import Budget"**
2. Choose import source:
   - YNAB4 (.ynab4 file)
   - YNAB5 (nYNAB export)
   - Actual Budget backup (.zip)
3. Upload file and follow prompts

### 3. Set Up Budget Basics

After creating your budget:

**Add Accounts:**
1. Click **"Add Account"** in sidebar
2. Choose account type:
   - **Checking** - Daily spending accounts
   - **Savings** - Savings accounts
   - **Credit Card** - Credit cards
   - **Investment** - Investment accounts (tracking only)
   - **Loan** - Mortgages, auto loans (tracking only)
3. Enter account details:
   - Name (e.g., "Chase Checking")
   - Starting balance
   - Optional: Off-budget (for tracking accounts)
4. Click **"Create"**

**Create Budget Categories:**
1. Click **"Budget"** tab
2. Click **"Add Category Group"** (e.g., "Monthly Bills", "Daily Expenses")
3. Click **"Add Category"** within group (e.g., "Rent", "Groceries", "Gas")
4. Repeat to build your category structure

**Suggested Category Groups:**
- **Monthly Bills:** Rent/Mortgage, Utilities, Phone, Internet, Insurance
- **Daily Expenses:** Groceries, Gas, Dining Out, Entertainment
- **Savings Goals:** Emergency Fund, Vacation, Down Payment
- **Debt Payments:** Credit Card, Student Loan, Auto Loan

### 4. Start Budgeting

**Assign Money to Categories:**
1. Go to **Budget** tab
2. Enter amounts you want to allocate to each category for this month
3. Watch "To Budget" amount decrease as you assign money
4. Goal: Reduce "To Budget" to $0 (every dollar has a job)

**Enter Transactions:**
1. Click **"Accounts"** tab
2. Select an account
3. Click **"Add Transaction"**
4. Fill in:
   - **Payee** (who you paid)
   - **Category** (what budget category)
   - **Amount** (positive for income, negative for expenses)
   - **Date**
5. Click **"Add"**

## Using Actual Budget

### Core Concepts

**1. Zero-Based Budgeting:**
- Every dollar you earn gets assigned to a specific category
- "To Budget" should be $0 when fully budgeted
- Unspent money from previous months rolls over

**2. Budget vs Accounts:**
- **Accounts** track actual money (checking, savings, credit cards)
- **Budget** is your plan for how to spend that money
- Same $1000 exists in both: account balance AND budget categories

**3. Overspending:**
- Red categories mean you spent more than budgeted
- Cover overspending by moving money from other categories
- Keep "To Budget" at $0 to maintain balance

### Common Workflows

**Monthly Budget Setup:**
1. At start of month, go to **Budget** tab
2. Click current month in header
3. Assign income to categories for the month
4. Adjust based on actual bills and expenses

**Reconciling Accounts:**
1. Go to **Accounts** tab
2. Select account to reconcile
3. Click **account name → "Reconcile"**
4. Enter current bank balance
5. Review discrepancies
6. Mark transactions as cleared

**Bank Import (Manual):**
1. Download CSV/OFX from your bank
2. Go to **Accounts** tab
3. Select account
4. Click **"Import Transactions"**
5. Upload file
6. Map CSV columns if needed
7. Review and import

**Tracking Net Worth:**
1. Add investment and loan accounts as "Off Budget"
2. Go to **Reports → Net Worth**
3. View assets minus liabilities over time

**Setting Savings Goals:**
1. Create category (e.g., "Emergency Fund")
2. Click category → **"Goal"** icon
3. Choose goal type:
   - **Target amount** (save $1000 total)
   - **Monthly contribution** (save $100/month)
   - **Target date** (save $500 by June)
4. Actual will show progress and suggest monthly amounts

### Multi-Budget Management

**Create Additional Budgets:**
1. Click budget name (top left)
2. Click **"Open Budget"**
3. Click **"Create New Budget"**
4. Manage personal, business, and family budgets separately

**Switch Between Budgets:**
1. Click budget name (top left)
2. Select budget from list

## Docker Compose Configuration

### File Location

`/home/vish/home-server/actual-budget/docker-compose.yml`

### Architecture

Actual Budget uses a two-container setup:

1. **actual_server** - The actual-budget Node.js application
2. **nginx** - Reverse proxy providing HTTPS (required for SharedArrayBuffer)

The containers communicate via a private Docker network (`actual-network`). Only the Nginx container exposes port 5006 to the host, providing secure HTTPS access.

### Service Details

#### Actual Server Container

**Container name:** `actual-budget`
**Image:** `docker.io/actualbudget/actual-server:latest`
**Internal port:** 5006 (not exposed to host directly)
**Restart policy:** unless-stopped (auto-starts on reboot)

#### Nginx Reverse Proxy Container

**Container name:** `actual-budget-nginx`
**Image:** `nginx:alpine`
**Port mapping:** 5006 (host) → 5006 (container, HTTPS)
**Purpose:** Provides HTTPS to enable SharedArrayBuffer
**Restart policy:** unless-stopped (auto-starts on reboot)

### Volume Mapping

| Service | Purpose | Container Path | Host Path |
|---------|---------|---------------|-----------|
| actual_server | Budget data, sync files, database | `/data` | `/mnt/storage/actual-budget` |
| nginx | Nginx configuration | `/etc/nginx/nginx.conf` | `./nginx.conf` |
| nginx | SSL certificates | `/etc/nginx/certs` | `/mnt/storage/actual-budget/certs` |

All budget files, user uploads, and sync data are stored in `/mnt/storage/actual-budget/` on the SSD (not SD card).
SSL certificates are stored in `/mnt/storage/actual-budget/certs/` (generated by `setup-ssl.sh`).

### Environment Variables

| Variable | Value | Purpose |
|----------|-------|---------|
| `TZ` | `America/Chicago` | Timezone for transaction dates and logs |

**Optional Configuration (commented out by default):**
- `ACTUAL_HTTPS_KEY` - Path to SSL key for HTTPS (not needed with Tailscale)
- `ACTUAL_HTTPS_CERT` - Path to SSL certificate
- `ACTUAL_PORT` - Override default port 5006
- `ACTUAL_UPLOAD_FILE_SYNC_SIZE_LIMIT_MB` - Max sync file size (default: 20MB)
- `ACTUAL_UPLOAD_SYNC_ENCRYPTED_FILE_SYNC_SIZE_LIMIT_MB` - Max encrypted sync size (default: 50MB)
- `ACTUAL_UPLOAD_FILE_SIZE_LIMIT_MB` - Max import file size (default: 20MB)

### Healthcheck

- **Check command:** `node src/scripts/health-check.js`
- **Interval:** Every 60 seconds
- **Timeout:** 10 seconds
- **Retries:** 3 attempts before marking unhealthy
- **Start period:** 20 seconds grace period on startup

### Network Access

| Type | URL | Notes |
|------|-----|-------|
| Local network | `https://192.168.0.104:5006` | Accessible from any device on home WiFi (HTTPS required) |
| Remote access | `https://100.126.21.128:5006` | Via Tailscale VPN only (HTTPS required) |

**Security Notes:**
- **HTTPS required:** SharedArrayBuffer (core technology) only works over HTTPS
- Self-signed certificate: Browser will show warning on first access (safe to proceed)
- Tailscale provides additional encrypted tunnel layer
- No authentication required for web access (password-protect in app if needed)
- Sync encryption optional but recommended for mobile devices

**Why HTTPS is Required:**
Actual Budget uses SharedArrayBuffer for high-performance budget calculations. Modern browsers require HTTPS (or localhost) to enable this feature for security reasons. The Nginx reverse proxy provides HTTPS using a self-signed certificate valid for your local network.

## Backup Strategy

### What to Backup

All critical data is stored in: `/mnt/storage/actual-budget/`

This directory contains:
- **Budget files** (`.sqlite` databases)
- **Sync metadata**
- **Uploaded transaction files**
- **User settings**

### Backup Methods

**Method 1: Built-in Budget Export (Recommended)**

```bash
# From web interface:
1. Open budget
2. Click Settings (gear icon)
3. Click "Download Backup"
4. Save .zip file to safe location
```

This creates a complete backup of the selected budget that can be imported into any Actual Budget instance.

**Method 2: Full Directory Backup**

```bash
# Backup entire data directory
sudo tar -czf /home/vish/backups/actual-budget-backup-$(date +%Y%m%d).tar.gz /mnt/storage/actual-budget/

# Restore from backup
cd /mnt/storage
sudo tar -xzf /home/vish/backups/actual-budget-backup-YYYYMMDD.tar.gz
sudo chown -R 1000:1000 /mnt/storage/actual-budget/
cd /home/vish/home-server/actual-budget
docker compose restart
```

**Method 3: Sync to Other Devices (Automatic)**

If sync encryption is enabled:
- Your budget syncs to mobile devices automatically
- Each device has a local copy
- Acts as distributed backup

### Backup Schedule Recommendation

- **Weekly:** Export budget via web interface
- **Monthly:** Full directory backup before major updates
- **Before updates:** Always backup before running `docker compose pull`

### Restore Individual Budget

```bash
# From web interface:
1. Click budget name (top left)
2. Click "Open Budget"
3. Click "Import Budget"
4. Upload .zip backup file
5. Budget restored with all transactions and settings
```

## Troubleshooting

### Issue 1: SharedArrayBuffer Error (Fatal Error)

**Symptoms:** Browser shows "Fatal Error: Actual requires access to SharedArrayBuffer"

**Cause:** This occurs when accessing via HTTP instead of HTTPS on a non-localhost address. Browsers restrict SharedArrayBuffer to secure contexts only.

**Solutions:**

1. **Use HTTPS URL (most common fix):**
   - Change `http://` to `https://` in browser address bar
   - Example: `https://192.168.0.104:5006` not `http://192.168.0.104:5006`
   - Accept the self-signed certificate warning

2. **Regenerate SSL certificates if local IP changed:**
```bash
cd /home/vish/home-server/actual-budget
./setup-ssl.sh
docker compose restart
```

3. **Verify Nginx is running:**
```bash
docker ps | grep actual-budget-nginx
```
Should show `actual-budget-nginx` container running

4. **Check Nginx logs for SSL errors:**
```bash
docker logs actual-budget-nginx
```

5. **Verify certificates exist:**
```bash
ls -la /mnt/storage/actual-budget/certs/
```
Should show `cert.pem` and `key.pem`

**Technical Details:**
Modern browsers require SharedArrayBuffer (used by Actual's SQLite engine) to be accessed via:
- HTTPS with proper COOP/COEP headers, OR
- localhost/127.0.0.1 only

Our setup uses Nginx to provide HTTPS with a self-signed certificate, which satisfies this requirement.

### Issue 2: Can't Access Web Interface

**Symptoms:** Browser shows "Can't reach this page" or "Connection refused"

**Solutions:**

1. **Verify both containers are running:**
```bash
docker ps | grep actual
```
Should show both `actual-budget` and `actual-budget-nginx` with status "Up"

2. **Check logs for errors:**
```bash
docker logs actual-budget
docker logs actual-budget-nginx
```
Look for "Listening on :::5006..." message in actual-budget logs

3. **Restart containers:**
```bash
cd /home/vish/home-server/actual-budget
docker compose restart
```

4. **Check port availability:**
```bash
netstat -tlnp | grep 5006
```
Should show Docker container listening on port 5006

5. **Verify correct URL:**
   - Local: `https://192.168.0.104:5006` (must use https://, includes :5006)
   - Tailscale: `https://100.126.21.128:5006`
   - Note: Local IP may change if using DHCP

### Issue 3: Self-Signed Certificate Warning

**Symptoms:** Browser shows "Your connection is not private" or "Warning: Potential Security Risk"

**This is NORMAL and SAFE for local network use.**

**Solutions:**

**Chrome/Edge:**
1. Click "Advanced"
2. Click "Proceed to 192.168.0.104 (unsafe)"

**Firefox:**
1. Click "Advanced"
2. Click "Accept the Risk and Continue"

**Safari:**
1. Click "Show Details"
2. Click "Visit this website"

**Why this happens:**
- The SSL certificate is self-signed (not from a trusted authority like Let's Encrypt)
- This is expected and safe for local network services
- The certificate was generated by your own setup script
- Traffic is still encrypted, just not verified by a third party

**To avoid warnings (optional):**
- Install the certificate in your OS trust store (advanced)
- Use localhost (no warning, but only works on the Pi itself)
- Set up Let's Encrypt with a domain name (complex for home networks)

### Issue 4: Mobile App Won't Sync

**Symptoms:** "Sync failed" or "Can't connect to server"

**Solutions:**

1. **Verify Tailscale is running on phone:**
   - Open Tailscale app
   - Should show green/connected status
   - Pi should be listed as online

2. **Test in mobile browser first:**
   - Open Safari/Chrome on phone
   - Go to: `https://100.126.21.128:5006` (must use `https://`)
   - Accept certificate warning if prompted
   - Should see Actual Budget interface

3. **Check sync encryption password:**
   - If you enabled encryption, mobile app needs same password
   - Web: Settings → Encryption → check password
   - Mobile: Re-enter password in app settings

4. **Re-add server in mobile app:**
   - Delete server from app
   - Add again with `https://100.126.21.128:5006` (must use `https://`)
   - Accept certificate if prompted
   - Download budget again

5. **Check network connectivity:**
```bash
# From server, check Tailscale status
tailscale status
```

**Symptoms:** Budget won't load, shows errors on open

**Solutions:**

2. **Restore from automatic backup:**


3. **Check disk space:**
```bash
df -h /mnt/storage
```
Corruption can occur if disk is full

### Issue 4: Container Won't Start

**Symptoms:** `docker compose up -d` fails or container keeps restarting

**Solutions:**

1. **Check logs for errors:**
```bash
docker logs actual-budget
```

2. **Verify storage is mounted:**
```bash

```

3. **Check permissions:**
```bash
ls -ld /mnt/storage/actual-budget/

```

4. **Remove container and recreate:**
```bash
cd /home/vish/home-server/actual-budget

```

5. **Check Docker daemon:**
```bash
sudo systemctl status docker
```

### Issue 5: Import Fails

**Symptoms:** CSV/OFX import shows errors or imports wrong data

**Solutions:**

1. **Check file format:**
   - Must be valid CSV, OFX, or QFX
   - CSV should have headers (Date, Payee, Amount, etc.)
   - File size under 20MB (default limit)

2. **Verify date format:**
   - Actual expects YYYY-MM-DD or MM/DD/YYYY
   - Check Settings → Formats if imports use different date format

3. **Manual column mapping:**
   - During import, manually map CSV columns
   - Date → Date column
   - Description/Memo → Payee column
   - Amount → Amount column

4. **Check for special characters:**
   - Remove non-ASCII characters from CSV
   - Re-save as UTF-8 encoded

### Issue 6: Sync File Size Too Large

**Symptoms:** "File too large to sync" error

**Solutions:**

1. **Increase upload limits (if needed):**
Edit `docker-compose.yml` and add:
```yaml
environment:
  - ACTUAL_UPLOAD_SYNC_ENCRYPTED_FILE_SYNC_SIZE_LIMIT_MB=100
```
Then restart: `docker compose up -d`

2. **Split large budget:**
   - Archive old transactions
   - Start fresh budget for new year
   - Keep old budget for reference

3. **Reduce transaction history:**
   - Delete very old transactions if not needed
   - Export for records first

### Issue 7: High CPU Usage

**Symptoms:** Raspberry Pi running hot, slow performance

**Cause:** Large budget sync or import processing

**Solutions:**
- **Normal during:**
  - Initial budget import
  - Large CSV file import
  - Sync after many changes
- Should stabilize after processing completes
- Monitor: `docker stats actual-budget`
- If persistent, check for corrupt sync file

### Issue 8: Lost Budget After Update

**Symptoms:** Budget disappeared after container update

**Solutions:**

1. **Check storage mount:**
```bash
ls -la /mnt/storage/actual-budget/
```
Budget files should still be there

2. **Restart container:**
```bash
cd /home/vish/home-server/actual-budget
docker compose restart
```

3. **Restore from backup:**
   - Use most recent .zip export
   - Import via "Open Budget" → "Import Budget"

### Expected Performance

**Raspberry Pi 5 (16GB RAM):**
- Budget with <1000 transactions: Near instant response
- Budget with 5000+ transactions: 1-2 second load time
- Import 500 transactions: 10-30 seconds
- Initial sync to mobile: 5-30 seconds depending on budget size

### Optimization Tips

1. **Archive old transactions:**
   - Delete transactions older than 2-3 years if not needed
   - Export first for tax records

2. **Limit simultaneous syncs:**
   - Don't sync 5 devices at once

3. **Use tracking accounts sparingly:**
   - Only add investment/loan accounts you actively monitor
   - Reduces overall transaction count

4. **Regular reconciliation:**
   - Reconcile accounts weekly
   - Catches errors early
   - Prevents data bloat from duplicate imports

**vs YNAB (You Need A Budget):**
- Actual is free and self-hosted vs YNAB $99/year

- Actual can import YNAB budgets

- Actual is privacy-focused (your server) vs Mint (Intuit's servers)

## Migration from Other Tools

### From YNAB

1. In YNAB: Export budget (File → Export Budget Data)
2. In Actual: Open Budget → Import Budget → Choose YNAB file
3. Review imported data
4. Set up sync encryption
5. Configure mobile apps

### From Mint

1. In Mint: Export transactions (Transactions → Export All)
2. In Actual: Create new budget
3. Add accounts matching Mint accounts
4. Import CSV for each account
5. Manually set up budget categories (Mint doesn't export budget plan)

### From Spreadsheets

1. Create new budget in Actual
2. Add accounts with current balances
3. Export CSV from spreadsheet with columns: Date, Payee, Category, Amount
4. Import transactions via Accounts → Import
5. Set up budget categories and allocations
